# Engineering Standard

Read before changing shared RatPack code.

State assumptions that materially affect implementation.

Read a file before editing it and inspect callers before changing shared functions.

Prefer the minimum change that satisfies the verified goal.

Do not refactor unrelated code during a feature or bug fix.

Define verifiable success criteria before implementation and loop until the checks pass.

Match the existing product style when touching legacy code unless the migration itself requires a deliberate standard change.

Avoid em and en dashes in Packrat written copy because the current brand and QA rules reject them.
